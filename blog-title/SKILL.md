# blog-title — 네이버 블로그 제목 5개 생성

박기린님 블로그 코퍼스의 실제 컨벤션을 근거로, 주제 한 줄 → 제목 후보 5개를 뽑습니다.

## 전제

- `./.claude/blog-corpus/index.json`이 존재해야 함. 없으면 먼저 `/blog-learn` 안내.
- 코퍼스가 비어 있거나 카테고리가 명백히 틀렸으면 추측하지 말고 사용자에게 카테고리를 물어볼 것.

## 입력

```
/blog-title "<주제>" [--category "<카테고리명>"] [--n 5]
```

예:
- `/blog-title "2026 SMKX 서울 키보드 박람회 방문기" --category "팝업/굿즈/오프"`
- `/blog-title "포코피아 47화 라프라스 전설 의뢰" --category "포코피아"`

`--category` 생략 시: 주제 키워드와 코퍼스의 카테고리·기존 제목을 매칭해 가장 적합한 카테고리를 추정한 뒤, **추정 결과를 사용자에게 1줄로 알리고** 진행. 추정 신뢰도가 낮으면 (매칭 점수 낮음) 사용자에게 카테고리를 되묻기.

## 절차

### 1. 패턴 추출

```bash
python3 ~/.claude/skills/blog-title/scripts/extract_patterns.py \
  ./.claude/blog-corpus --category "<카테고리>"
```

출력 JSON에서 다음을 읽어 컨벤션 모델링:
- `tags`: 그 카테고리에서 실제로 사용된 `[]` 태그 전체 (count 포함)
- `kind_words`: 트레일링 토큰 분포 (예: 팝업 5, 굿즈 2, 굿즈탐방 1) → 어떤 "형태" 어휘가 정착되어 있는지
- `ip_words`: 리딩 토큰 분포 → IP/브랜드 표기 방식
- `subtitle_samples`: `]` 뒤 본문 패턴 (구분자, 길이감, 날짜 포함 여부)
- `subtitle_delimiters`: `/` 사용 빈도

### 2. 컨벤션 진단

추출 결과로부터 **이 카테고리에서 관측된 규칙**을 명시적으로 정리. 예:
- 태그 형식: `[IP/브랜드 + 형태]` 2단어 조합 (단일어 케이스도 N건 존재)
- 형태 어휘 후보: 가장 자주 쓰이는 trailing 토큰 N개 중 주제에 맞는 것 선택
- 본문 구조: `방문기 / 부제 / 날짜` 슬래시 구분 (관측된 경우만)

이 진단을 출력에 1~2줄로 짧게 표시 (사용자가 왜 그 패턴을 따랐는지 검증할 수 있게).

### 3. 후보 5개 생성

각 후보는 다음을 만족:
- **태그**: 카테고리에서 관측된 `[IP 형태]` 패턴을 따른다. 새 형태 어휘를 도입할 땐 기존 어휘 중에 적합한 게 없을 때만, 그리고 길이 10자 이내로.
- **본문 제목**: 주제 안에 있는 **공식 명칭을 그대로** 사용 (왜곡·임의 약어화 금지). 예: "서울 키보드 박람회"는 줄이지 말 것.
- **부제**: 카테고리에서 관측된 패턴을 따라 슬래시 `/`로 부제·날짜 구성. 부제는 본문 단어 단순 반복이 아니라 추가 정보(서브토픽, 날짜, 인상평 등).
- **태그-본문 단어 중복**은 사용자 기존 글에서 이미 허용됨 (예: `[명조 굿즈] 명조빵`). 일부 중복은 OK, 같은 단어 3회 이상 반복은 피할 것.

후보 5개는 서로 차별성을 가져야 함 (전부 똑같은 부제 패턴이면 무의미). 권장 다양성:
1. 가장 안전한 컨벤션 그대로 (추천)
2. 부제 강화형 (인상·핵심 키워드 부각)
3. 날짜 포함형 (관측되는 경우)
4. 태그 약어/풀네임 변형형 (예: `[SMKX 박람회]` vs `[키보드 박람회]`)
5. 부제 톤 변형형 (감정적·궁금증 유발)

### 4. 출력 (필수 템플릿)

마크다운으로 다음 형식 정확히 출력:

```
## 카테고리: <카테고리명> (관측 N개 글)

**관측 컨벤션**: [<IP> + <형태>] / 본문 / 부제 (구분자: `/`)

**제목 후보 5개**:

1. **[추천]** [태그] 본문 / 부제
2. [태그] 본문 / 부제
3. [태그] 본문 / 부제 / 2026.MM
4. [태그variant] 본문 / 부제
5. [태그] 본문 / 부제 (톤 변형)

**사유 한 줄씩**:
1. — 왜 이게 안전한지
2. — ...
3. — ...
4. — ...
5. — ...
```

### 5. 자체 검수

다음을 출력 전에 확인하고, 위반 시 재작성:

- [ ] 이모지 0개 (`grep -P '[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}]'`로 점검 가능)
- [ ] 주제 안의 공식 명칭이 후보 5개 중 최소 3개에서 변형 없이 보존됨
- [ ] 모든 후보가 카테고리에서 관측된 형태 어휘 또는 그 자연스러운 확장만 사용
- [ ] 태그 길이 12자(공백 포함) 이하

## 하드룰

- **이모지 금지**. 한 글자도 쓰지 말 것.
- **행사·브랜드명 왜곡 금지**. SMKX의 "서울 키보드 박람회"를 임의로 "키보드 쇼"로 줄이거나 표기를 바꾸지 말 것. 약어가 필요하면 (1) 공식 약어, (2) 영문 원어 중에서만 선택.
- **카테고리는 `index.json`에 실제 존재하는 것만**. 새 카테고리 만들지 말 것.
- 카테고리 추정 시 신뢰도가 낮으면 후보 출력 전에 사용자에게 되물을 것.
- 코퍼스가 비어 있으면 추측으로 추천하지 말 것. `/blog-learn` 먼저 돌리도록 안내.

## 기존 글 리네이밍 모드

사용자가 "기존 글 제목도 다시 뽑아줘"라고 하면:
- `extract_patterns.py` 출력의 `tags`에서 컨벤션을 벗어난 태그(예: 단일어인데 같은 카테고리 다수가 2단어인 경우)를 식별
- 해당 글들에 대해서만 후보 1~2개씩 제안
- **일괄 변경 비추천 안내**: 네이버는 제목 변경 시 검색 캐시 재인덱싱이 필요해 일시적 노출 흔들림 발생. 트래픽 적은 옛 글 위주로 점진 정비를 권장.
