# blog-topic-brief — 주제 사전조사 + 네이버 블로그 제목/태그 브리프

웹 검색으로 사실관계를 먼저 잡고, 그 위에서 제목/태그를 추천하는 스킬. `blog-title`이 "사용자가 이미 아는 주제"를 코퍼스 기반으로 다듬는 반면, 이 스킬은 "사용자가 잘 모르는 주제"를 외부에서 끌어오는 것이 핵심.

## 전제

- WebSearch + WebFetch 도구 사용 가능해야 함.
- 코퍼스(`./.claude/blog-corpus/index.json`)는 **선택 사항**. 있으면 코퍼스 갈래도 같이 추천, 없으면 일반 SEO 갈래만.
- 주제에 등장하는 고유명사(이벤트명, 게임명, 아이템명)는 **공식 표기를 검색으로 확정**한 뒤 사용. 사용자가 쓴 호칭과 공식 표기가 다르면 둘 다 메모.

## 입력

```
/blog-topic-brief "<주제 한 줄>" [--category "<카테고리>"] [--n 3]
```

예:
- `/blog-topic-brief "포코피아 깜까미 붉은 광석 모으기 이벤트"`
- `/blog-topic-brief "2026 서울 키보드 박람회 후기 글감" --category "팝업/굿즈/오프"`

`--n` 기본값 3, 가변(2~5). `--category` 생략 시 검색 결과와 코퍼스를 매칭해 추정.

## 절차

### 1. 웹 검색 (필수)

1. WebSearch로 주제 키워드 1차 검색. 한국어 표기와 영문 표기 모두 시도해도 좋음.
2. 상위 결과 중 **공식 사이트 · 위키(나무위키 등) · 전문 가이드 사이트** 1~2개를 WebFetch로 정밀 확인. 커뮤니티/블로그는 보조 참고만.
3. 다음을 메모:
   - 정식 명칭(공식 표기) — **딱 하나로 확정**. 출처 간 표기가 갈리면 공식 사이트/게임 인게임 표기 우선
   - 기간/일정(있으면 마감일까지)
   - 핵심 메커니즘·요구사항
   - 보상·결과물
   - 사용자가 쓴 호칭과 공식 표기의 차이 (예: "붉은 광석" ↔ "빨간 크리스탈 조각")
4. **동의어 함정 주의**: 의미상 같은 단어(수정 ↔ 크리스탈, 광석 ↔ 보석)라도 공식 표기와 다르면 비공식 표기. 공식 표기 하나만 본문·제목·핵심 태그에 사용. 동의어를 "별칭"으로 취급해 병기하지 말 것 — 별칭은 사용자 커뮤니티가 실제로 쓰는 비공식 호칭만 해당.

검색 결과가 빈약하거나 상충하면 **추측하지 말고** 사용자에게 어떤 출처를 우선할지 되묻기.

### 2. 코퍼스 진단 (코퍼스 있을 때만)

```bash
python3 ./blog-title/scripts/extract_patterns.py \
  ./.claude/blog-corpus --category "<카테고리>"
```

(설치 경로에 따라 `~/.claude/skills/blog-title/scripts/extract_patterns.py`)

출력에서 읽을 것:
- `tags`: 해당 카테고리의 `[]` 태그 컨벤션
- `kind_words` / `ip_words`: 형태 어휘·IP 어휘 분포
- `subtitle_delimiters`: 부제 구분자(주로 `/`)

`--category` 추정 신뢰도가 낮으면 사용자에게 카테고리 1회 되묻기.

### 3. 출력 구성 (Markdown)

다음 4개 섹션을 **이 순서로** 출력.

#### 3-1. `## 주제 팩트 정리`
- 정식 명칭, 기간, 핵심 메커니즘, 보상, 선행조건을 불릿으로
- 사용자 호칭 ↔ 공식 표기 차이가 있으면 명시
- 길이는 6~10줄 권장

#### 3-2. `## 제목 추천 — 코퍼스 컨벤션 기반` (코퍼스 있을 때만)
- `blog-title`과 동일한 `[IP 형태]` 패턴을 따름
- `--n`개 후보 + 각 후보 끝에 한 줄 사유
- 첫 번째 후보에 `**[추천]**` 표시
- 부제 구분자는 코퍼스에서 관측된 것 사용

#### 3-3. `## 제목 추천 — 일반 SEO 기반`
- 코퍼스와 무관하게 네이버 SEO 룰로 작성
- `--n`개 후보, 각각 **서로 다른 전략**:
  - 정공법(키워드 풀스택, 검색 유입 최우선)
  - 호기심 후킹형(체험·후기 톤, "~해봤습니다", "~정리")
  - 마감 임박/체크리스트형(CTR 최적화, 마감일/숫자 포함)
  - 그 외 가능: 비교형, Q&A형
- 각 후보 끝에 어떤 케이스에 적합한지 한 줄

코퍼스가 없으면 이 섹션만 출력. 있으면 두 갈래 모두 출력하고 마지막에 **어떤 갈래를 권장하는지 한 줄** 결론.

#### 3-4. `## 태그 추천 (15~25개)`
- 코드블록으로 카피 용이하게
- 구성: **단일어 태그 + 합성 태그 + 별칭 태그**를 섞는다
  - 단일어: `#포코피아`, `#깜까미`, `#빨간크리스탈조각`
  - **합성(필수, 최소 2~3개)**: IP명/게임명을 prefix로 붙인 붙여쓴 태그. 네이버는 띄어쓰기 변형 매칭이 약해서, 단일어만으로는 "포코피아 빨간 크리스탈" 같은 멀티키워드 롱테일 유입을 놓침. 예: `#포코피아깜까미`, `#포코피아빨간크리스탈`, `#포코피아빨간크리스탈조각`
  - 별칭: 사용자가 쓴 비공식 호칭도 1~2개 보조 추가 (예: `#붉은광석`). 본문·제목은 공식 표기만 유지
- 순서: 핵심 단일어 → 핵심 합성 → 카테고리/플랫폼 → 별칭/롱테일
- 길이: 단일어는 12자 이내 우선, 합성 태그는 길어져도 OK (네이버 한 태그 길이 제한 관대)

#### 3-5. `Sources:` (필수)
- WebSearch 결과 룰대로 모든 인용 URL을 마크다운 링크로 명시.

### 4. 자체 검수 (출력 전)

위반 시 재작성:

- [ ] 이모지 0개
- [ ] 공식 명칭이 본문·제목·핵심 태그 모두에서 변형 없이 보존됨 (별칭은 태그 보조 위치에만)
- [ ] 사용자 호칭과 공식 표기가 다르면 팩트 정리 섹션에 명시됨
- [ ] **동의어 임의 병기 없음**: 의미가 같다는 이유로 비공식 표기(예: "수정")를 공식 표기(예: "크리스탈") 옆에 끼워넣지 않음. 단일 공식 표기만 사용
- [ ] 제목 앞 30자 안에 핵심 키워드 3개 이상 진입
- [ ] 코퍼스 갈래 후보가 코퍼스에서 관측된 형태 어휘만 사용
- [ ] Sources 섹션이 있고 링크가 유효함

## 하드룰

- **이모지 금지**. 한 글자도 쓰지 말 것.
- **행사·브랜드·아이템 공식 표기 왜곡 금지**. 검색으로 확정한 공식 표기를 본문·제목·핵심 태그에서 유지. 사용자가 쓴 다른 호칭은 별칭으로만 태그 끝부분에 보조 추가.
- **코퍼스 없으면 코퍼스 갈래를 생략**. 코퍼스 부재 시 추측으로 `[]` 패턴을 만들지 말 것. 필요하면 `/blog-learn`을 먼저 돌리도록 안내.
- **출처 필수**. WebSearch를 썼다면 Sources 섹션은 반드시 응답 끝에 출력.
- 검색 결과가 부족하거나 상충하면 추측하지 말고 사용자에게 되물을 것.

## 사용 흐름 예시

```
사용자: "포코피아 깜까미 붉은 광석 모으기 이벤트에 대해 검색하고 네이버 블로그 제목/태그 추천"
스킬:
  1) WebSearch "포코피아 깜까미 빨간 수정 조각 이벤트"
  2) WebFetch 공식 가이드 페이지 1~2
  3) 팩트 정리 (이벤트 명칭: 깜까미와 보석 모으기 이벤트, 공식 아이템: 빨간 수정 조각, 사용자 호칭: 붉은 광석)
  4) 코퍼스 있으면 → 코퍼스 갈래 + 일반 SEO 갈래 둘 다
     코퍼스 없으면 → 일반 SEO 갈래만
  5) 태그 15~25개 (공식 표기 + 별칭 보조)
  6) Sources
```

## 관련 스킬

- `/blog-learn` — 코퍼스가 없을 때 먼저 돌려야 코퍼스 갈래 활성화됨.
- `/blog-title` — 주제를 이미 잘 알 때 제목 5안만 빠르게.
- `/blog` — 본문까지 자동 작성하는 풀파이프라인. 이 스킬의 출력(팩트 정리)을 입력으로 넘기면 자연스러움.
