데브로그(docs/blog/devlog/)를 기린파크 블로그 글로 변환할 때, 합니다체 전환·문단 쪼개기만으로는 부족하다. 독자는 게임 블로그 이웃이지 개발자가 아니다.

**Why:** 1편 변환에서 "4096 기반 고정소수점 모디파이어", "정수 모디파이어", "내림" 세 표현에 연속으로 "무슨 뜻이냐" 피드백을 받음 (2026-06-12). 어미는 블로그체였지만 어휘는 개발자 레지스터 그대로였던 것이 원인.

**How to apply:**
- 기능/화면의 문제를 다루기 전에, 그 기능이 뭔지 한두 문장으로 먼저 소개할 것 (예: 파티빌더 — "내 파티 6마리를 짜는 화면"). 독자는 앱을 본 적이 없다 (2편 피드백)
- 코드블록 해설은 코드 아래에 배치. 코드 위에는 맥락 연결 한 줄("그래서 규칙을 둘로 나눴습니다")만, 코드가 뭘 하는지 설명은 전부 코드 밑에 (2편 피드백, 3편부터 적용)

**4편 피드백 (2026-06-13) — 표현 금지 목록:**
- 비유 신조어 금지: "관문", "요청 창구", "콘센트 규격", "플러그", "인증 제공자" 전부 거부됨. 평범한 단어(서버, 기능, 틀)로 쓰고 수량은 숫자로("기능 8개", "여덟 개" 금지)
- "원칙은 하나였습니다" 류 원칙 프레이밍 금지. 그냥 "한 번에 다 바꾸지는 않았습니다"처럼 서술
- 동기 서술은 "~기능을 구현하려고 보니 확장이 필요했다" 식으로. "로드맵에 들어오면서" 같은 내부용어 금지
- 시리즈 연결 장치 전면 금지: 본문 백레퍼런스("N편에서 만든") 금지, 도입부 이전 편 링크 목록도 금지, 글 끝 다음 편 예고도 금지. 각 글은 독립적으로
- 글 끝 "다음 편은 ~입니다" 예고 금지
- 구어 포장 어미 금지: "~더라고요", "~거든요", "~면 끝이죠", "~게 전부였죠", "~모양으로요" 전부 거부됨. 평서문으로 담백하게. ("로그인 방식이 뭐든 서버가 하는 일은 같습니다. 자격 정보를 받아서, 누구인지 확인해주면 끝이죠" → "인증 로직은 공통 인터페이스로 추상화했습니다")
- 제목은 한 일 그대로: "NestJS 적용" (O), "서버를 통째로 갈아엎기" (X) — 과장·드라마화 금지
- 제목 부제는 명사 나열 금지("계정·로그인·하루 사용 한도" X)하되, "~만들기"를 기계적으로 붙이는 것도 거부됨("하루 사용 한도 만들기" X). 자연스러운 동작 명사로: "로그인 구현과 AI 사용량 제한" (O)
- 단계는 "3단계"/"4단계" 각각 절로. "3·4단계" 병기 금지
- 의인화 따옴표 대사 금지: '둘 다 "지금 1개네, 통과"를 보고' (X) → "둘 다 개수를 세는 시점에는 1개뿐이라 둘 다 통과되고" (O). 사실 서술로
- 도입부는 "안녕하세요. 박기린입니다." 인사로 시작. 시리즈 링크 목록은 넣지 않음 (한때 현자 시리즈 형식으로 넣었다가 2026-06-13 전면 금지됨)

**4편 2차 피드백 (2026-06-13) — 어휘 방향 대전환:**
- 개발 용어는 한국어 직역·비유로 풀지 말고 **현업 용어 그대로**: request body 검증, Zod 스키마, class-validator DTO, 트랜잭션, upsert 쿼리, 인터페이스/구현체, export/import, tsup 번들, dist, node 서브패스. 어설픈 한국어 비유("부품", "틀", "쪼개질 수 없는 한 묶음", "명령 한 방")가 오히려 더 거슬림. ※ 쉽게 풀기는 게임 개념·일반 독자용 설명에만 적용 (1편 "내림→169×1.5=253" 피드백과 공존하는 규칙: 게임/수학 개념은 풀고, 개발 실무 용어는 그대로)
- 자뻑·과시 멘트 전면 금지: "이게 전문입니다", "이게 전부입니다", "가장 잘한 일은" 류 삭제. 코드 소개는 사실만 ("이름과 authenticate 메서드 하나뿐인 인터페이스입니다")
- 문장 + 짧은 선언 나열 리듬("~확인해준다. 이게 전부입니다.") = 중2병으로 거부됨. 담백한 평서문으로
- 강제로 쪼갠 명사문("기능은 그대로, 뼈대만 교체.") 금지. 작업 방식 메타 서술("네 단계로 쪼갰습니다", "범위를 좁혀야 원인을 찾는다", "단계마다 테스트로 묶어뒀습니다" 요약 재진술)도 쓸데없는 표현으로 거부됨 — 한 일만 적고 방법론 해설은 생략
- 장식 수식어 금지: "화면 뒤, 서버 이야기" (X) → "서버 이야기" (O)
- 당연한 귀결 반복 금지: "기존 코드는 안 바뀝니다", "본체 코드는 한 줄도 안 바뀝니다" 류 — 구현체만 추가하면 된다고 했으면 거기서 끝
- 지시 대상 항상 명시: "계산 라이브러리" (X) → "데미지·실수치 계산을 담당하는 패키지(pokedex-core, battle-engine)" (O)
- 제목 최종형은 사용자가 "AI 조언 사용량 제한"으로 직접 다듬음 — 기능 이름을 정확히 (AI 사용량 X, AI 조언 사용량 O)
- 전문용어가 글의 주인공이면: 한 줄 풀이 + 게임 숫자 구체 예시 (예: 내림 → "169 × 1.5 = 253.5가 253이 된다")
- 조연이면: 단어 자체를 일상어로 대체 (모디파이어 → 없애고 "4096 기준 숫자")
- 추상 서술 금지, 항상 구체 숫자로
- 경계 단어들: 결정론, fixture, 회귀, 레벤슈타인, 도메인 계층, 마이그레이션, 스키마, 튜플
- 채팅에서 복붙용 문안을 줄 때 인용(>) 블록 금지 — 복사하면 깨짐. 코드펜스 박스로 줄 것
- 제목 태그는 카테고리명과 1:1 ([포챔스 사이드킥]), 시리즈 번호가 있으니 "제작기" 같은 중복어 불필요
- 태그는 "#태그1 #태그2" 공백 구분 형식으로 제공
- 본문 맨 밑에도 해시태그 라인을 구분선 뒤에 넣을 것 (4편부터, 사용자 지시 2026-06-13). 사이드바 진짜 태그는 여전히 사용자가 직접 입력
