# game-progress-tracker — 블로그 진행상황으로 남은 분량·글감 예측

게임 제목 한 줄을 받아:
1. 박기린님 블로그의 그 게임 연재글에서 **현재 어디까지 했는지** 읽고,
2. 웹에서 **전체 진행 구조**를 찾아 **남은 분량**을 계산하고,
3. 남은 구간의 **길이·서브스토리·섹션**을 조사한 뒤,
4. 박기린님의 **연재 글쪼개기 패턴**을 학습해 **앞으로 나올 블로그 글 개수와 글감**을 예측합니다.

## 원칙

- **사실 확인은 실제 발행 글에서.** 말투 학습용 `./.claude/blog-corpus/`를 보지 말고, 네이버에 발행된 실제 글 본문을 받는다. (코퍼스는 사실 소스가 아니다.)
- **조회 시점 기준 최신 정보.** 진행 구조는 기억에 의존하지 말고 웹검색으로 확인한다.
- **진행 단위는 게임마다 다르다.** 챕터(붉은사막), 체육관 배지+포켓몬리그(포켓몬 본가), 신전/사당·지역(젤다), 메인퀘스트 등. 게임에 맞는 단위로 환산하고, 단위 이름을 그대로 쓴다("챕터"로 억지 통일 금지).
- **출처 신뢰도 순위.** 한국어 게임은 나무위키 > 공식/인벤 가이드 > game8/powerpyx 등 영문 위키 > SEO 가이드. SEO끼리 베껴 쓴 수치(총 퀘스트 수, 100% 시간 등)는 확정으로 단정하지 않는다.
- **고유명사는 그 게임의 정식 표기를 교차검증해서 쓴다.** 기억으로 음차/직역하지 말 것.
  - 한글 정식 로컬라이징이 있는 게임 → 정식 한국어명(나무위키·공식 위키로 확인). 예: 포켓몬 Vermilion=갈색시티(탱탱시티 아님), Sevii Islands=일곱섬.
  - 한글 발매/번역이 없는 게임 → 영문 정식 표기(또는 한국 커뮤니티 통용 표기)로 간다. 억지 음차·창작 한글명 금지.
  - 영문·한글이 혼재해 들어오면(사용자가 영문으로 부르는데 정식 한글명이 따로 있는 등) 정식 표기 쪽으로 통일하되, 한 번은 "정식명(흔히 부르는 명)"으로 병기해 혼선을 막는다.
- **이모지 금지.** 게임명·구간명·보스명을 임의로 축약/의역하지 않는다.

## 입력

- 게임 제목 (예: `붉은사막`, `젤다 왕눈`, `파이어레드`). 블로그 태그 `[게임명]` 기준 매칭.
- (옵션) 블로그 ID — 기본값 `op5321`.

## 절차

### 1. 블로그에서 연재글·최신 진행상황 수집 (스크립트, 결정적)

```bash
python3 game-progress-tracker/scripts/blog_game_progress.py "<게임 제목>"
```

출력 JSON에서 확인:
- `matched_count` / `posts[]` — 그 게임 연재글 목록(최신순).
- `latest` — 최신화 제목·URL·`body_excerpt`(본문 발췌).
- `available_tags` / `hint` — **매칭이 0~1개면** 자동으로 따라온다. 연재 태그가 축약형일 수 있으니(예: `파이어레드`→`포켓몬 파레리그`) `available_tags`에서 맞는 태그를 골라 그 태그로 **재실행**한다.

스크립트가 하는 일(직접 재구현 금지):
- `PostTitleListAsync.naver` 페이지네이션으로 전체 글 수집 (RSS는 최근 50개뿐이라 못 씀)
- 게임 제목으로 필터(대괄호·공백 무시), `logNo` 최대값 = 최신화
- 최신화 본문을 `m.blog.naver.com` 모바일 UA로 받아 태그 제거
- 매칭 저조 시 전체 글의 `[태그]`별 빈도 제공

### 2. 최신화에서 현재 위치 판별

`latest.body_excerpt`에서 현재 진행 지점을 찾는다.
- 예(붉은사막): "피의 대관식 - 타오르는 불꽃 스토리를..." → 현재 = 챕터8 **피의 대관식**.
- 예(파레리그): "이슬이의 두 번째 배지 획득" → 현재 = 관동 **2번째 배지(블루시티 이슬)**.
- **블로그 연재 번호(32화)는 게임 진행 단위가 아니다.** 한 구간이 여러 화로 쪼개진다. 반드시 본문에서 실제 지점(구간명/보스/배지/지명)을 읽어 판단.
- 본문에 단서가 없으면: 보스·지명·퀘스트명을 키워드로 3단계 웹검색에 넘겨 역추적하거나, 발췌를 사용자에게 보여주고 확인.

### 3. 전체 진행 구조 웹검색

```
WebSearch: "<게임> 메인 스토리 챕터 순서 목록"   (포켓몬이면 "배지 순서 체육관 관장", 젤다면 "신전/지역 순서")
WebSearch: "<game> main story chapter list in order"
```
프롤로그·에필로그·엔딩 후 콘텐츠 포함 전체 순서를 신뢰도 높은 출처로 확정한다.

### 4. 남은 분량 계산

- 전체 구조에서 현재 위치(2단계)를 찾는다.
- **남은 분량 = 현재 구간 이후의 모든 단위 + 엔딩 후 콘텐츠**, 현재 구간이 진행 중(미완)이면 명시.
- 가장 긴 구간 등 체감 분량 정보가 있으면 덧붙인다.

### 5. 남은 구간 상세 조사 (길이·서브스토리·섹션)

남은 각 구간(또는 최소한 바로 다음 1~2구간)에 대해 웹검색으로:
- **길이**: 퀘스트 수 / 예상 플레이타임 (출처 신뢰도 순위 적용, 단정 금지)
- **주요 서브스토리·이벤트**: 그 구간의 핵심 사건·보스·선택지
- **하위 섹션**: 그 구간을 자연스럽게 나눌 수 있는 단위(지역 이동, 보스전, 던전 등)

### 6. 블로그 글 개수·글감 예측

먼저 **박기린님의 글쪼개기 패턴을 1단계 `posts[]` 제목에서 역산**한다. 글 한 편이 보통 무엇 하나를 다루는지:
- 붉은사막: 보스 1~2 + 퀘스트 단위 (예: "지혜의 마녀"를 4성소 = 4편으로 분할)
- 파레리그: 도시/도로 구간 + 배지 단위 (예: "달맞이산~블루시티 + 배지" = 1편)

그 다음, 5단계의 섹션 수에 이 패턴을 적용해 **남은 구간별 예상 글 수와 글 제목 후보**를 만든다.
- 형식 예: "챕터9 사막의 현자(퀘스트 25개) → 예상 3~4편: ① 도입·○○ 도착 ② △△ 보스전 ③ □□ 공략 ④ 마무리"
- 제목 톤은 박기린님 기존 제목 컨벤션(`[게임] N. 구간 : 핵심 키워드`)을 따르되, **고유명사·구간명은 정확히**. 제목까지 뽑을 땐 `blog-title` 스킬과 연계 가능.

### 7. (후속) 노션 '게임' 태스크보드에 할 일 추가 — 반드시 물어보고 실행

6단계 보고 뒤 물어본다: **"이 게임 할 일을 노션 '게임' 태스크보드에 추가할까요?"** 동의(ㅇㅇ/응/추가해)할 때만 실행. 거부면 끝낸다. (노션 변경은 되돌리기 번거로우니 무단 실행 금지.)

대상 = **개인 WS(pos000830, self=박요셉)**. 회사 블루밍그레이스 아님. 라이브 ID(2026-06-25 확인, 404면 `notion-search`로 재탐색하고 [[project-notion-lifeos]] 갱신):
- 태스크보드 ds `f03c6f40-e87e-8359-9dd9-07a786a10ef3`
- 미디어 ds `1e0c6f40-e87e-826c-97e5-8763f9b9d0cf` (유형 select에 `게임` 옵션 이미 있음)
- 프로젝트 ds `641c6f40-e87e-82f4-9f1f-879d3a856f35`

실행 순서:
1. **미디어 upsert**: 그 게임이 미디어 DB에 있는지 `notion-search`로 확인. 없으면 `create-pages`로 1행(제목=정식 한국어명, 유형=게임, 상태=진행 중, 제작자). 있으면 그대로 두고 url만 확보. ("있으면 냅두고" — 중복 생성 금지.)
2. **게임 프로젝트 확보**: 프로젝트 DB에 `게임` 행 없으면 생성(분류=취미, 상태=진행 중). url 확보.
3. **태스크 생성 — 반드시 한 건씩 순차로**. `create-pages`를 게임 순서대로 1페이지씩 호출. **batch(한 호출에 여러 페이지) 금지** — 작업ID 단조성이 깨질 수 있음.
   - 태스크 단위 = 6단계의 **섹션 단위**("갈색시티 : S.S.앙느호", "갈색시티 : 마티스(3배지)", "보라타운 : 포켓몬타워"…). 도시/챕터 묶음이 아니라 그 안 세부 이벤트.
   - 속성: 할 일(섹션명), 상태=Backlog, 프로젝트=`["<게임 프로젝트 url>"]`, 관련 미디어=`["<게임 미디어 url>"]`. 관계값은 페이지 URL의 JSON 배열 문자열.
4. **순서 보존 = 작업ID 단조성** (사용자 선택, 2026-06-25 검증: 순차 생성 시 작업ID 22→23으로 생성순서대로 부여). 별도 순서 컬럼·제목 번호 안 씀. 게임 순서대로 보려면 태스크보드 뷰를 **작업ID ASC** 정렬. `게임`만 거르는 뷰의 프로젝트(relation) 필터는 create-view DSL로 안 걸리니 UI에서 1회 설정.

함정: query-data-sources(SQL·view)는 이 WS에서 Business 전용이라 막힘 → 행 존재확인은 search/fetch로만. semantic이라 놓칠 수 있으니 정확 일치 우선, 애매하면 사용자에게 확인.

## 출력 형식

1. **현재 위치** — 최신화 제목·날짜 + 게임 진행상 지점 (근거: 본문 인용 한 줄)
2. **전체 진행 맵** — 처음~엔딩(+후반 콘텐츠), 현재 위치 표시. 단위는 게임에 맞게.
3. **남은 분량** — 남은 단위 N개 (현재 구간 미완 여부 명시)
4. **남은 구간 상세** — 길이·주요 서브스토리·섹션 (조사한 만큼)
5. **블로그 글 예측** — 구간별 예상 글 개수 + 글감/제목 후보
6. **노션 추가 제안** — "'게임' 태스크보드에 추가할까요?" (동의 시 7단계 실행)
7. **Sources** — 사용한 URL 마크다운 링크 (나무위키/공식 우선 + 블로그 최신화)

## 함정 / 주의

- WebFetch는 naver를 차단한다 → 스크립트의 curl/urllib 경로만 사용.
- `PostTitleListAsync` JSON은 invalid escape 포함 → `json.loads` 깨짐. 스크립트는 정규식 파싱으로 우회(직접 손대지 말 것).
- **태그 축약 매칭**: 사용자가 부르는 이름(파이어레드)과 연재 태그(포켓몬 파레리그)가 다를 수 있다. 매칭 0~1이면 `available_tags`로 재실행. 영문 질문이면 한국어 정식명으로도 시도.
- **진행 단위 오인 금지**: 챕터 없는 게임(포켓몬=배지, 젤다=신전/지역)을 억지로 "챕터"라 부르지 말 것.
- 글 개수 예측은 **추정**임을 명시. 게임 구조와 박기린님 페이스에 따라 달라진다고 한 줄 단서.
- 웹검색 요약이 구간 순서를 틀리게 줄 수 있다(SEO 노이즈) → 블로그 본문의 실제 라벨과 교차검증.
- **지명·고유명사 교차검증(원칙 참고).** 출력·글감 제목에 쓰기 전 표기를 확정한다. 한글 정식명이 있으면 나무위키/공식 위키로 교차검증, 한글 미발매 게임이면 영문/통용 표기로 유도리 있게. namu.wiki는 WebFetch 403 → `curl`에 브라우저 UA로 받는다. 참고 메모리: [[feedback-korean-pokemon-lexicon]].
- 관련 메모리: [[blog-fetch-real-post-not-corpus]], [[naver-automation-osascript-route]]. 제목 뽑기는 `blog-title` 스킬.
