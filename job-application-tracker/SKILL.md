# 채용 공고 → 지원 현황 DB 입력

박요셉(op5321)의 Notion "지원 현황" DB에 채용 공고를 일관된 형식으로 정리해 넣는 스킬.
사용자가 공고 URL이나 JD 텍스트를 보여주면, 공고를 읽고 → 속성을 매핑하고 → 본문을 채운다.

## DB 위치 (고정 좌표)

- 데이터베이스 페이지: `지원 현황` — `352fd0c1-f4f9-4ecd-bc46-a6e43eb3c471`
- 데이터소스(collection): `42bc0796-609b-4068-bcc5-d1204d1945bc`  ← 페이지 생성 시 `parent.data_source_id`로 사용
- 상위 페이지: `업무관리`

작업 시작 전 `notion-fetch`로 `collection://42bc0796-609b-4068-bcc5-d1204d1945bc`를 한 번 조회해 스키마(옵션 값)가 바뀌지 않았는지 확인하면 안전하다. ID가 더 이상 유효하지 않으면 `notion-search`로 "지원 현황"을 찾아 갱신한다.

## 공고 읽기 (중요)

대부분의 채용 사이트(특히 `careers.nhn.com`)는 JavaScript로 렌더링되므로 **WebFetch로는 본문이 안 나온다**(제목만 옴). 반드시 브라우저로 읽는다:

1. `tabs_context_mcp`로 컨텍스트 확보 → `tabs_create_mcp`로 새 탭 생성
2. `navigate`로 공고 URL 이동
3. `get_page_text`로 본문 텍스트 추출

여러 공고면 같은 탭에서 `navigate` → `get_page_text`를 반복하면 된다.
사용자가 JD 텍스트를 직접 붙여넣었으면 브라우저 없이 그 텍스트를 그대로 쓴다.

## 속성 매핑

데이터소스에 `notion-create-pages`로 새 페이지를 만든다. 속성 규칙:

| 속성 | 타입 | 채우는 법 |
|---|---|---|
| `회사` | title | 회사/계열사명 그대로 (예: `NHN LINK`, `테서`). 고유명사 왜곡 금지 |
| `직무` | text | 짧은 포지션명 (예: `프론트엔드`, `티켓링크 프론트엔드 개발자`) |
| `상태` | select | 신규는 항상 `검토`. 지원 의사 없으면 `제외` |
| `적합도` | select | 아래 루브릭으로 ★~★★★★★ 판정 |
| `요구 경력` | select | 아래 매핑 |
| `기술스택` | multi_select | JSON 배열 문자열. 아래 옵션만 사용 |
| `근무지역` | text | 공고의 근무지 주소 전체 |
| `공고링크` | url | 공고 URL |
| `메모` | text | 한 줄 매치 요약(스택 매치도·약점·도메인). 본문과 중복 길게 쓰지 말 것 |
| `마감일` | date | 상시채용이면 비움. 명시 마감일 있을 때만 `date:마감일:start` |
| `지원일` | date | 지원 전이므로 비움 |

### 기술스택 옵션 (이 목록 밖은 `기타`)
`React`, `React Native`, `TypeScript`, `JavaScript`, `Next.js`, `Vue`, `Node.js`, `Flutter`, `iOS`, `Android`, `기타`
- 형식: `"[\"React\", \"TypeScript\"]"` (JSON 배열을 문자열로)
- 공고의 핵심 스택을 고른다. 우대사항에만 살짝 언급된 건 넣어도 되고 빼도 된다(판단).

### 요구 경력 옵션
`신입`, `1~3년`, `3~5년`, `5~10년`, `10년+`, `무관`
- "5년 이상" → `5~10년`, "6년 이상" → `5~10년`, "10년 내외" → `10년+`, "경력 무관"/"연차 무관" → `무관`
- 범위가 옵션 경계에 걸치면 하한 기준으로 보수적으로 고른다.

## 적합도 루브릭

적합도는 **이 공고가 후보자에게 얼마나 맞는지**를 본다. 후보자 기준 프로필:

> 프론트엔드 개발자, 약 3~4년차. 주력 스택: React, Next.js, TypeScript, Zustand, TanStack Query.
> React Native 앱 + 웹 SaaS 병행 경험. LLM 도구(Cursor/Claude) 실무 활용은 이미 충족.
> 약점: Next.js 프로덕션 심화, styled-components/Storybook, 차트·데이터 시각화, 금융 도메인, 대규모 트래픽.

(프로필이 바뀌었으면 사용자에게 확인하거나, `업무관리`의 자기소개서/이력서 항목을 참고해 갱신한다.)

기존 항목에서 관찰된 채점 기준:
- `★★★★★` — 자격요건 스택이 주력 스택과 거의 완전 일치하고 경력 요건이 `무관` 또는 충족. (예: 테서 — Zustand+TanStack 명시, RN+웹 동일, 무관)
- `★★★★` — 핵심 스택 매치, 일부 약점 영역 존재. 경력 트랙은 "또는 이에 준하는 역량"으로 지원 가능. (예: 네이버페이비상장 — 차트/금융이 약점)
- `★★★` — 스택은 맞으나 요구 경력이 후보자보다 명확히 높음(5년+/6년+) 등 갭 존재.
- `★★` — 경력 갭이 크거나(10년+) 팀 리드/멘토링이 자격요건. 현 시점 재도전 성격. (예: 카카오페이증권 — 5~10년+팀리드)
- `★` — 스택/도메인이 거의 안 맞음.

적합도는 추정치이므로, 입력 후 **사용자에게 "이 점수가 맞는지" 확인받고 조정**한다. 멋대로 확정하지 않는다.

## 페이지 본문 형식

본문은 `insert_content`로 채운다. 기존 항목과 **동일한 섹션·순서**를 지킨다. 모든 내용은 공고 원문에 충실하게(왜곡·창작 금지):

```markdown
## 매치 분석            ← 선택. 스택 매치도/경력 갭/면접 포인트 2~3줄
## 주요업무            ← 공고 "주요업무" 불릿
## 자격요건            ← 공고 "자격요건" 불릿
## 기술스택 (공고 원문)  ← 공고에 명시된 스택/도구 원문
## 우대사항            ← 공고 "우대사항" 불릿
## 복지·혜택           ← 공고에 있으면. 없으면 생략
## 마감               ← "상시채용" 또는 마감일 + 근무지
```

- 공고에 없는 섹션은 생략한다(없는 걸 지어내지 않는다).
- 면접 절차가 특이하면(예: 바닐라 JS 라이브코딩, 포트폴리오 필수) `## 매치 분석`이나 `## 채용절차`에 적어 두면 사용자가 대비하기 좋다.
- 포트폴리오 제출 필수 같은 **지원 전 준비물**은 눈에 띄게 적는다.

## 작업 순서

1. (필요시) `notion-fetch`로 데이터소스 스키마 확인
2. 공고 읽기 — 브라우저 `get_page_text` 또는 붙여넣은 텍스트
3. 공고마다 속성 매핑 + 본문 초안 작성
4. `notion-create-pages`로 행 생성 (여러 공고는 한 번에 `pages` 배열로)
5. 각 페이지에 `insert_content`로 본문 채우기
6. `update_properties`로 `적합도` 설정
7. 사용자에게 표로 요약 보고 + 적합도/요구경력 추정값 확인 요청

## 예시 (요약)

입력: `https://careers.nhn.com/recruits/3985816522460747079` "채용 db 채워줘"

→ 브라우저로 읽은 결과: NHN LINK, 티켓링크 프론트엔드, 5년 이상, React/TS/jQuery, 강남, 상시채용, 1차 바닐라 JS 라이브코딩

→ 생성:
- 회사 `NHN LINK` / 직무 `티켓링크 프론트엔드 개발자` / 상태 `검토` / 요구경력 `5~10년`
- 기술스택 `["React","TypeScript","JavaScript"]` / 근무지역 `서울 강남구 강남대로 586`
- 적합도 `★★★` (스택 매치하나 5년+ 요건, 라이브코딩 대비 필요)
- 본문: 주요업무/자격요건/기술스택/우대사항/마감 + 매치 분석
