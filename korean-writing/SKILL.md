# korean-writing: 한국어 산문 작성과 검증

새로 쓰는 한국어 글을 규약대로 쓰고, 검사기와 적대적 검증 두 단계로 확인합니다.

## 규칙 정본

규칙은 `references/rules.md` 한 곳에만 있습니다. 이 SKILL.md에 규칙을 다시 적지 않고,
규칙을 고칠 때도 그 파일만 고칩니다. `CLAUDE.md`에는 요약만 있습니다.

정규식으로 판정할 수 없는 항목은 `references/judgments.md`의 판정법이 담당합니다.

## 적용 범위

한국어 산문에만 적용합니다. 다음은 대상이 아닙니다.

- 영어로 쓰는 코드리뷰, 커밋 메시지, PR 설명
- 변수명, 주석, 로그 문자열, enum 값, 식별자
- 전사와 이관 스킬의 산출물. `notion-to-naver`, `tistory-to-naver`, `naver-to-naver`,
  `js-lecture-publish`는 문장 창작이 금지된 스킬입니다
- 제목과 태그만 뽑는 스킬. `blog-title`, `naver-blog-tags`, `blog-topic-brief`

외국어를 한국어로 번역하라는 규약이 아닙니다. 한국어를 쓰는 자리에서 그 한국어를
명확하게 쓰라는 규약입니다.

## 실행 경로

### 작성 경로

사용자가 새 글을 요청했을 때입니다.

1. 프로파일을 고릅니다.
2. `references/rules.md`와 해당 프로파일을 읽습니다.
3. 초안을 씁니다.
4. 검증 2단계를 돌립니다.
5. 초안과 검증 결과를 함께 제시합니다.

### 검수 경로

사용자가 이미 쓴 글을 주면서 검사를 요청했을 때입니다. 초안을 쓰지 않고 검증만 돌립니다.

`고침` 갈래도 사용자 확인 없이 파일에 반영하지 않습니다. 남이 쓴 글일 수 있습니다.

## 프로파일 선택

사용자가 산출물 종류를 말했으면 그대로 씁니다. 말하지 않았으면 아래로 판정하고,
애매하면 사용자에게 묻습니다.

| 신호 | 프로파일 |
|---|---|
| 수신자가 있고 요청이나 보고가 목적 | `references/profiles/email.md` |
| 코드나 PR에 대한 지적 | `references/profiles/code-review.md` |
| 슬랙, 깃허브, 피그마의 답글 | `references/profiles/thread.md` |
| 네이버 블로그 초안 | `blog` 스킬로 넘김 |

프로파일에 따라 달라지는 것은 구조 규칙뿐이고 문체 규칙은 전부 공통입니다. 잘못 골라도
문체 검사는 동일하게 걸립니다.

## 1단계: 검사기

```bash
python3 korean-writing/scripts/lint.py 초안.md
python3 korean-writing/scripts/lint.py 초안.md --fix
python3 korean-writing/scripts/lint.py 초안.md --heuristic
python3 korean-writing/scripts/lint.py 초안.md --json
cat 초안.md | python3 korean-writing/scripts/lint.py -
```

출력은 네 갈래입니다.

| 갈래 | 처리 |
|---|---|
| 고침 | 확정 위반입니다. `--fix`가 자동으로 치환합니다 |
| 검토 | 문맥을 보고 사람이 결정합니다. 제안을 그대로 넣지 않습니다 |
| 제목 | 헤더를 명사구로 고칩니다 |
| 의심 | `--heuristic`을 줄 때만 나옵니다. 메일과 코드리뷰에서만 켭니다 |

종료 코드가 0이 아니면 아직 끝난 것이 아닙니다. `검토` 갈래를 남긴 채 글을 내밀 때는
무엇을 왜 남겼는지 사용자에게 말합니다.

`--fix`는 파일을 다시 쓰므로 줄바꿈이 LF로 통일됩니다. CRLF를 유지해야 하는 파일에는
`--fix`를 쓰지 않고 보고만 받습니다.

걸린 표현을 지워서 검사기를 피하지 않습니다. 인용이 꼭 필요한 자리는 백틱이나 낫표로
감싸거나 줄 끝에 `<!-- write-exempt -->`를 답니다. 금지 표현을 예시로 보여주는 표는
바로 앞에 `<!-- write-teaching -->`을 둡니다.

## 2단계: 적대적 검증

검사기가 잡을 수 없는 항목을 서브에이전트가 봅니다. 의인화, 광의 고유어, 번역투,
정보 없는 추임새, 문장 쪼개기, 극적 서두, 홍보 문구가 대상입니다.

Agent 도구로 에이전트를 하나 띄우고 `references/judgments.md` 끝의 지시문을 그대로
전달합니다. 대상 원고의 경로를 함께 줍니다.

에이전트는 보고만 하고 원고를 고치지 않습니다. 수정 여부는 사용자가 결정합니다.

### 실행 조건

원고가 300자 미만이면 1단계만 돌립니다. 코드리뷰 코멘트 세 줄에 에이전트를 띄우는 것은
낭비입니다. 300자 이상이거나 사용자가 요청하면 2단계까지 갑니다.

## 검사 범위

본문 산문만 보면 다음이 빠집니다. 매번 확인합니다.

- 절 제목. 서술형 제목이 가장 자주 남습니다
- 표의 좌변과 우변. 교정안도 같은 규칙을 통과해야 합니다
- 목록 항목과 캡션
- 규칙을 서술하는 문장 자신. 규약을 설명하면서 규약을 어기는 일이 실제로 일어납니다

## 판단이 필요한 경우

기계적으로 적용하면 안 되는 자리가 있습니다. 다음은 사용자에게 확인합니다.

- 인용문. 남의 말을 옮긴 자리를 규약대로 고치면 인용이 아니게 됩니다
- 고유명사와 행사명, 표준명. 임의로 바꾸면 글이 틀린 것이 됩니다
- 조직 내부에 굳어진 용어
- 사실 자체를 남겨야 하는 정정 고지. 톤을 부드럽게 하더라도 수치 정정과 기준 변경은
  남깁니다
- 채울 내용이 없어 비워 둔 자리. 홍보 문구로 메우지 말고 사용자에게 묻습니다

## 회귀 검사

```bash
python3 korean-writing/scripts/test_lint.py
```

픽스처 두 벌과 스킬 자신의 문서를 검사합니다. 규칙을 추가하면 `scripts/fixtures/`에
사례를 함께 넣습니다.
