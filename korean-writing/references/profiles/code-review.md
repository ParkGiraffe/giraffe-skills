# 코드리뷰 프로파일

문체 규칙은 `references/rules.md`가 정본이며 여기에 다시 적지 않습니다. 이 문서는
코드리뷰 코멘트의 구조 규칙만 담습니다.

한국어로 쓰는 코멘트에만 적용합니다. 영어로 쓰는 리뷰는 이 스킬의 대상이 아닙니다.

## 지적의 구성

지적 하나는 세 조각으로 씁니다. 관찰, 근거, 대안입니다. 셋 중 하나라도 빠지면 취향
표명이 됩니다.

<!-- write-teaching -->

| 쓰지 않습니다 | 씁니다 |
|---|---|
| 이 부분 이상합니다. | `retryLimit`이 0일 때 while 문이 즉시 빠져나가서 재시도가 한 번도 일어나지 않습니다. 기본값을 3으로 두거나 0을 무한 재시도로 해석하는 편이 낫습니다. |

## 단정 대신 관찰

무엇이 잘못됐다고 선언하기 전에 무엇을 보았는지 씁니다. 코드가 실제로 그렇게 동작하는지
확인하지 않은 지적은 확인하지 않았다고 밝힙니다.

`이건 버그입니다`보다 `입력이 빈 배열이면 여기서 IndexError가 납니다`가 낫습니다.
후자는 재현 조건을 담고 있어 상대가 바로 확인할 수 있습니다.

## 번역하지 않는 것

코드 식별자, enum 값, 필드명, 로그 문자열은 번역하지 않습니다. `SUCCESS`를 성공으로
적으면 코드와 코멘트가 어긋납니다.

규격과 API에 등장하는 말은 영문 표기를 씁니다. 원어와 하나씩 대응해야 검색과 대조가
됩니다.

<!-- write-teaching -->

| 쓰지 않습니다 | 씁니다 |
|---|---|
| 페이로드 | `payload` |
| 엔드포인트 | `endpoint` |
| 콜백 | `callback` |

## 분량

코멘트 하나는 화면 한 눈에 들어와야 합니다. 근거가 길어지면 코멘트가 아니라 이슈나
문서로 옮기고 코멘트에는 링크만 남깁니다.

## 검사

```bash
python3 korean-writing/scripts/lint.py 코멘트.md --heuristic
```

코멘트가 300자 미만이면 검사기만 돌리고 적대적 검증은 건너뜁니다.
