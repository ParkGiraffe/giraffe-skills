# 쓰레드 프로파일

슬랙 쓰레드, 깃허브 이슈와 PR 쓰레드, 피그마 코멘트에 적용합니다. 문체 규칙은
`references/rules.md`가 정본이며 여기에 다시 적지 않습니다.

## 공통 구조

결론을 먼저 씁니다. 쓰레드는 읽는 사람이 알림으로 받아 첫 줄만 보는 경우가 많습니다.

마크다운 구분선과 표를 쓰지 않습니다. 슬랙은 표를 렌더링하지 않고, 구분선은 화면 폭에
따라 깨집니다.

질문에 답할 때는 질문을 다시 옮겨 적지 않고 바로 답합니다.

## 슬랙과 깃허브

- 첫 줄에 결론을 씁니다. 근거는 그 아래에 붙입니다.
- 코드와 로그는 코드 블록으로 감쌉니다. 본문에 섞으면 읽히지 않습니다.
- 여러 사람에게 각각 다른 요청이 있으면 요청마다 줄을 나누고 대상을 앞에 적습니다.
- 결정이 필요한 사안은 무엇을 결정해야 하는지 한 줄로 분리해 씁니다.

## 피그마 코멘트

피그마 코멘트는 특정 요소에 앵커가 붙지만, 쓰레드가 길어지거나 디자인이 바뀌면 무엇에
대한 말이었는지 사라집니다. 따라서 어느 요소를 가리키는지 먼저 적습니다.

<!-- write-teaching -->

| 쓰지 않습니다 | 씁니다 |
|---|---|
| 이거 간격이 좀 넓은 것 같아요 | 상단 탭바와 카드 리스트 사이 여백이 32px입니다. 다른 화면은 24px이라 맞추는 편이 좋겠습니다. |

- 요소 이름과 수치를 함께 적습니다. 화면에서 짚어 주는 말은 코멘트에 남지 않습니다.
- 짧게 씁니다. 근거가 길어지면 코멘트가 아니라 문서로 옮기고 링크만 남깁니다.
- 대안을 함께 적습니다. 문제만 적으면 디자이너가 다시 물어야 합니다.
- 확정 요청인지 의견인지 밝힙니다. 피그마 코멘트는 둘이 섞이면 반영 여부가 흐려집니다.

## 검사

```bash
python3 korean-writing/scripts/lint.py 답변.md
```

쓰레드 답변은 짧으므로 `--heuristic` 없이 돌립니다. 광의 고유어 규칙은 짧은 답변에서
과합니다.
