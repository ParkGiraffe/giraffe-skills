# 글쓰기 규칙 정본

박기린(op5321)의 한국어 산문 규약입니다. 이 파일이 정본이며 `scripts/lint.py`가 이 표를
읽어 검사합니다. 규칙 추가는 표에 행을 넣는 것으로 끝나야 하고, 규칙을 코드에 옮겨 적지
않습니다.

## 표 형식

검사 대상 표는 다음 다섯 열을 갖습니다. 열 이름이 `찾기`로 시작하는 표만 규칙으로 읽습니다.

| 열 | 값 |
|---|---|
| 찾기 | 리터럴 문자열, 또는 백틱으로 감싼 정규식 |
| 바꾸기 | 대체 문자열. 삭제 대상이면 `(삭제)`, 사람이 정해야 하면 `(직접)` |
| 갈래 | `고침` / `검토` / `제목` / `의심` |
| 검출 | `literal` / `regex` |
| 범위 | `prose` / `heading` / `list` / `table` / `all` |

정규식 안의 세로줄은 `\|`로 적습니다. 마크다운 표가 깨지기 때문입니다. 검사기가 읽을 때
되돌립니다.

갈래의 뜻은 다음과 같습니다.

| 갈래 | 처리 |
|---|---|
| 고침 | 확정 위반입니다. `--fix`가 자동으로 치환합니다 |
| 검토 | 문맥을 보고 사람이 결정합니다. 자동 치환하지 않습니다 |
| 제목 | 헤더가 명사구가 아닌 경우입니다 |
| 의심 | `--heuristic`을 줄 때만 보고합니다. 오탐 가능성이 높습니다 |

## 1. 확정 금지 문자

이모지는 한 글자도 쓰지 않습니다. Notion callout 아이콘처럼 블록 속성으로 들어가는
이모지도 포함합니다.

엠대시는 제목, 불릿 정의, 코드 주석, 참고문헌 어디에도 쓰지 않습니다. 콜론이나 쉼표로
바꾸거나 문장을 나눕니다.

## 2. 금지 상투구

자족적으로 읽혀야 하므로, 필요하면 개념 이름을 그대로 다시 씁니다.

## 3. 어체

모든 문장을 `~입니다` / `~합니다` 체로 씁니다. 구어체 종결어미와 감탄사를 쓰지 않습니다.

아래 표는 자주 나오는 확정 치환입니다. 표에 없는 종결형은 검사기가 문장 종결을 직접 보고
합쇼체가 아니면 `검토`로 보고합니다. 표가 목록이 아니라 자동 치환 대상이라는 뜻입니다.

헤더, 표 셀, 명사구로 끝나는 목록 항목에는 강제하지 않습니다. 목록 불릿까지 `~입니다`로
끝내면 글이 늘어집니다.

| 찾기 | 바꾸기 | 갈래 | 검출 | 범위 |
|---|---|---|---|---|
| `한다(?=[.\n]\|$)` | 합니다 | 고침 | regex | prose |
| `된다(?=[.\n]\|$)` | 됩니다 | 고침 | regex | prose |
| `이다(?=[.\n]\|$)` | 입니다 | 고침 | regex | prose |
| `있다(?=[.\n]\|$)` | 있습니다 | 고침 | regex | prose |
| `없다(?=[.\n]\|$)` | 없습니다 | 고침 | regex | prose |
| `아니다(?=[.\n]\|$)` | 아닙니다 | 고침 | regex | prose |
| `않는다(?=[.\n]\|$)` | 않습니다 | 고침 | regex | prose |
| `같다(?=[.\n]\|$)` | 같습니다 | 고침 | regex | prose |
| `많다(?=[.\n]\|$)` | 많습니다 | 고침 | regex | prose |
| `좋다(?=[.\n]\|$)` | 좋습니다 | 고침 | regex | prose |
| `했다(?=[.\n]\|$)` | 했습니다 | 고침 | regex | prose |

## 4. 문장 구조

의미가 있는 문장 성분을 생략하지 않습니다. 필수적인 경우가 아니면 조사와 어미도
생략하지 않습니다. 명사구나 연결어미로 문장을 끝내지 않고 서술어와 종결어미로 맺습니다.

한 문장으로 쓸 수 있는 것을 두 문장으로 끊지 않습니다. 결론을 뒤로 미루려고 서두를 던진 뒤
정체를 다음 문장에서 밝히는 구성도 쓰지 않습니다. 이 둘은 정규식으로 판정할 수 없으므로
2단계 적대적 검증이 담당합니다.

| 찾기 | 바꾸기 | 갈래 | 검출 | 범위 |
|---|---|---|---|---|
| `함(?=[.\n]\|$)` | (직접) | 검토 | regex | prose |
| `됨(?=[.\n]\|$)` | (직접) | 검토 | regex | prose |
| `임(?=[.\n]\|$)` | (직접) | 검토 | regex | prose |
| `있음(?=[.\n]\|$)` | 있습니다 | 검토 | regex | prose |
| `없음(?=[.\n]\|$)` | 없습니다 | 검토 | regex | prose |
| `필요(?=[.\n]\|$)` | 필요합니다 | 검토 | regex | prose |
| `하고(?=[.\n]\|$)` | (직접) | 검토 | regex | prose |
| `지만(?=[.\n]\|$)` | (직접) | 검토 | regex | prose |
| `인데(?=[.\n]\|$)` | (직접) | 검토 | regex | prose |

## 5. 어휘

영어 기술 용어를 기계적으로 직역하지 않습니다. row-level을 "행 단위", coarse-grained를
"거친 권한"으로 옮기면 한국어로는 뜻이 잡히지 않습니다. 무엇을 검사하고 무엇을 하는지로
풀어 씁니다.

번역서 말투를 쓰지 않습니다. 개발자가 실제로 쓰는 말로 씁니다.

아래 광의 고유어 표는 갈래가 `의심`입니다. 기술 문서와 계약 문서에서는 의미역을 좁혀야
하지만, 블로그와 쓰레드 답변에서는 고유어가 더 자연스럽습니다. `--heuristic`을 줄 때만
보고하며, `email`과 `code-review` 프로파일에서만 사용을 권합니다.

| 찾기 | 바꾸기 | 갈래 | 검출 | 범위 |
|---|---|---|---|---|
| `다룹니다` | 한정합니다 · 규정합니다 · 정의합니다 | 의심 | regex | prose |
| `넘깁니다` | 전달합니다 · 이관합니다 · 위임합니다 | 의심 | regex | prose |
| `맞춥니다` | 정합합니다 · 정렬합니다 · 보정합니다 | 의심 | regex | prose |
| `나눕니다` | 구분합니다 · 분류합니다 · 배분합니다 | 의심 | regex | prose |
| `지웁니다` | 삭제합니다 · 제거합니다 · 소거합니다 | 의심 | regex | prose |
| `잡습니다` | 검출합니다 · 산정합니다 · 고정합니다 | 의심 | regex | prose |
| `막습니다` | 차단합니다 · 방지합니다 | 의심 | regex | prose |
| `행 단위` | (직접) | 검토 | literal | all |
| `거친 권한` | (직접) | 검토 | literal | all |

## 6. 제목

제목은 명사구로 씁니다. 서술형 제목은 논평처럼 읽히고 글을 고칠 때 낡습니다.
제목은 주제를 지시하고 주장은 본문이 합니다.

제목에 따옴표를 쓰지 않습니다. 대사와 인용은 본문 안에서만 씁니다.

이 절은 표가 아니라 검사기의 헤더 판정으로 처리합니다. 다음에 해당하면 `제목` 갈래로
보고합니다.

- `다` 또는 `까`로 끝나는 헤더
- 물음표나 느낌표로 끝나는 헤더
- `은가` / `는가` / `한가` / `인가`로 끝나는 헤더
- 의문사로 시작하는 헤더
- `~하는 방법` / `~하는 과정` / `~하는 이유` / `~할 때` / `~할 것` / `~하기`로 끝나는 헤더

이미 명사구인 `처리 방법`, `저장 과정`, `확인 사항`은 유지합니다.

## 7. 검사 제외 목록

아래 목록의 표현은 다른 절의 규칙에 걸려도 보고하지 않습니다. 고유명사와 표준명을
임의로 변형하면 글이 틀린 것이 됩니다.

## 8. 홍보 문구 금지

영화 슬로건, 공식 시놉시스 문장, 제작사 카피를 글감이나 근거로 끌어오지 않습니다.
제작사가 만든 말이지 본 사람의 감상이 아닙니다. 관람 동기나 작품 해석의 근거로 쓰면
글이 광고를 옮긴 것이 됩니다.

조사한 자료 중 눈에 띄는 문구로 빈칸을 메우려는 습관에서 나오므로, 채울 것이 없으면
비워 두고 사용자에게 묻습니다.

정규식으로 판정할 수 없으므로 2단계 적대적 검증이 담당합니다.
