# naver-blog-tags — 네이버 블로그 태그 추출·추천

박기린(`op5321`)이 쓴 글에 달 네이버 블로그 해시태그를 뽑는 스킬.
단순히 키워드를 나열하지 않고, **실제 검색 수요(연관검색어) + 사용자 본인의 기존 태그 형식 + 공식 표기**
세 축으로 교차검증해 단일어 태그와 합성 태그를 함께 제시한다.

블로그 환경: 네이버 `blog.naver.com/op5321`, 티스토리 정리본 `arnopark.tistory.com`.

## 언제 쓰나
- "이 글 네이버 태그 뽑아줘 / 추천해줘 / 만들어줘"
- 글 본문(붙여넣기)이나 글 URL을 주면서 태그를 요청할 때
- "태그 한 줄로 줘", "클립보드에 복사해줘" 같은 후속 요청 포함

## 4단계 워크플로

### 1. 글 읽고 키워드 추출
- 입력은 셋 중 하나: (a) 붙여넣은 본문, (b) 티스토리 URL, (c) 네이버 글 URL/logNo.
  - 티스토리는 `curl`(아이폰 UA)로 본문·`rel="tag"` 추출.
  - 네이버는 **WebFetch 금지** → `curl`(아이폰 UA + Referer)로만. `scripts/user_tag_style.py --logno <N>`로 기존 태그까지 디코드.

> **제목·태그의 정본(SSOT)은 무조건 네이버 원본.** 티스토리 정리본은 참고용 백링크일 뿐, 제목 서식을 훼손하므로(대괄호 안 공백 제거 `[포켓몬 GO]`→`[포켓몬GO]`, 구분자 `:`→`/`, 뒤에 ` | 정리본` 추가) **제목·화수의 근거로 티스토리를 읽지 말 것.** 네이버 최신 글 목록·제목·`logNo`를 직접 열거하는 API가 curl로 된다:
> ```bash
> curl -s -A "Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15" \
>   -H "Referer: https://m.blog.naver.com/op5321" \
>   "https://m.blog.naver.com/api/blogs/op5321/post-list?categoryNo=0&itemCount=30&page=1"
> ```
> JSON `result.items[]` 각 항목의 `titleWithInspectMessage`(제목, HTML 이스케이프)·`logNo`를 읽는다(파싱 예: `python3 -c "import sys,json,html; d=json.load(sys.stdin); [print(p.get('logNo'), html.unescape(p.get('titleWithInspectMessage',''))) for p in d['result']['items']]"`). 여기서 `[카테고리 ]` 제목을 grep해 시리즈 **최대 화수 +1**을 확정하고(네이버 기준, 티스토리 아님), `logNo`로 그 글의 `tagNames`를 디코드해 실제 태그를 확인한다. (네이버 RSS·모바일 홈 HTML은 curl로 비어서 안 됨 → 이 API가 정답.)
- 본문에서 **고유명사·이벤트명·아이템명·지명·시스템명·수치(레벨 등)**를 개체 단위로 추출.
  예) 260레벨, 하이퍼버닝 MAX, 버닝 BEYOND, 6차 전직, 어센틱심볼 세르니움, 챌린저스 패스, 운영자 사과/OVERDRIVE.

### 2. 네이버·구글 연관검색어와 대조
```bash
python3 scripts/related_keywords.py "키워드1" "키워드2" ...
```
- 네이버 자동완성(`ac.search.naver.com`) = **타깃 플랫폼이라 1순위 신호**, 구글 suggest는 보조.
- 반환된 멀티키워드 조합이 합성 태그의 직접 근거가 된다.
  예) "포코피아 지라치" → `포코피아 지라치 서식지` 가 뜨면 `#포코피아지라치서식지`가 정당화됨.
- 오타·비공식 표기도 같이 보임(구글이 "포토피아" 노출) → 4단계 공식 표기 점검에 활용.

### 3. 내 기존 글의 태그 형식 학습 (가장 중요)
```bash
python3 scripts/user_tag_style.py "<검색어>"          # 예: "메이플", "포코피아", "하이퍼버닝"
python3 scripts/user_tag_style.py --logno 224321870566 224324010450   # 직접 지정
```
- 원리: 사용자는 **네이버에 먼저 쓰고 티스토리에 '정리본' 백링크**를 만든다.
  스크립트가 `arnopark.tistory.com/search/<검색어>`로 정리본을 찾고 → 본문의 `m.blog.naver.com/op5321/<logNo>`
  백링크를 따라가 → 네이버 글 HTML의 `tagNames` JSON(`\"tagNames\":\"\uXXXX,...\"`)을 디코드한다.
- **같은 IP/카테고리의 가장 비슷한 글**(예: 레벨 달성 글, 이벤트 글)의 태그가 새 글 태그의 템플릿.
- 여기서 사용자 고유의 **합성 규칙**을 읽어낸다. 실측된 패턴:
  - `#게임명`(메이플)과 `#게임명풀네임`(메이플스토리)을 **항상** 둘 다
  - `게임명+X` 합성 prefix를 **대량으로** (`#메이플하이퍼버닝MAX`, `#포코피아통통코이벤트`)
  - 주요 개체는 **합성 + 맨단어 페어** (`#메이플챌린저스` + `#챌린저스`, `#포코피아통통코` + `#통통코`)
  - 이벤트: `#게임명이벤트` + `#게임명+개체+이벤트`
  - 서식지/가구: `#게임명+개체+서식지`, `#게임명+개체+가구`
  - 레벨: `#게임명+숫자+렙` (메이플240렙)
  - 직업/캐릭터 태그 포함(소울마스터)

### 4. 공식 표기·한국 커뮤니티 표기로 정제
- **포켓몬류에서 오역 사고가 잦다**(영어 직역, 의미상 동의어 치환). 반드시:
  - 등장 고유명사의 **공식 한글 표기를 딱 하나** 확정(WebSearch + 사용자 기존 태그 + 인게임 표기).
  - 사용자 본인이 과거 글/대화에서 쓴 표기가 **최우선 정답**(인게임에서 가져온 것이라). 예: 소원 아이템 = "소원 종이"/"반짝반짝 소원 종이"(소원 메모·탄자쿠 아님).
  - 제3자 공략 사이트 표기는 **신뢰하지 말 것**(과거 "빨간 크리스탈 조각"을 "빨간 수정 조각"으로 오기한 전례).
- **동의어를 공식 표기처럼 병기·치환하지 말 것**(수정↔크리스탈, 광석↔보석, 메모↔종이). 같은 뜻 다른 표기를 둘 다 넣으면 공식 표기의 정확 매칭 점수가 분산된다.
- 같은 개념의 **표기 변형(렙/레벨, 비욘드/BEYOND)도 하나만** — 검색량 큰 쪽을 택하고 나머지는 뺀다.
- 비공식 호칭(커뮤니티 별칭)은 **별칭 태그 1~2개 슬롯에만** 보조로. 본문·제목·핵심 태그엔 안 씀.

## 출력 규칙
- 단일어 + 합성 + (필요시)별칭을 섞어 **15~25개** 권장(길고 많아도 OK — 사용자 명시 선호).
- 합성 태그(IP명 prefix)를 **반드시 다수** 포함. 빠뜨리면 멀티키워드 롱테일 유입을 놓친다.
- 그룹(핵심/이벤트/아이템/서식지/공략/광역)으로 보여주되, 요청 시 **공백 구분 한 줄**로도 제시.
- 이모지 금지(리포 하드룰).

## 클립보드 저장 (바로 복사)
**박기린은 매번 묻지 말고 바로 복사를 선호**(명시 지시: "앞으로는 바로 복사도 진행하자"). 태그를 다 뽑으면 **확인 없이 곧바로** 클립보드에 저장하고 `pbpaste`로 검증한다.

### 복사 형식 (2블록 고정 — 2026-08-04 사용자 지시, 2026-08-07 재확인)
클립보드에는 **전체 세트(최대 개수) → 빈 줄 2개 → 핵심 8~12개** 순으로 한 번에 담는다.
사용자가 상황에 따라 위쪽(전체)이나 아래쪽(핵심)을 골라 붙여넣기 때문에 **두 블록을 항상 같이** 넣는다.
"핵심만 다시 뽑아줘"를 매번 요청하게 만들지 말 것.

**사용자가 "핵심 8~12개만 복사해줘"라고 요청해도 2블록으로 복사한다** (2026-08-07 지시).
"~만"은 핵심 블록을 보여달라는 뜻이지, 전체 세트를 빼라는 뜻이 아니다.
단일 블록만 넣는 경우는 사용자가 "전체 빼고", "한 줄만"처럼 명시적으로 배제했을 때뿐이다.

```
#태그1 #태그2 ... #태그27


#핵심1 #핵심2 ... #핵심10
```

`clip.py`는 줄바꿈을 단일 공백으로 정규화하므로 **2블록 형식에는 쓸 수 없다.** `pbcopy`에 직접 넣는다:
```bash
python3 - <<'PY'
import subprocess
full = "#태그1 #태그2 ..."
core = "#핵심1 #핵심2 ..."
payload = full + "\n\n\n" + core          # 빈 줄 2개
subprocess.run(["pbcopy"], input=payload.encode("utf-8"), check=True)
assert subprocess.run(["pbpaste"], capture_output=True).stdout.decode() == payload
PY
```
단일 블록만 필요할 때(사용자가 명시)는 기존 `clip.py`를 그대로 쓴다:
```bash
python3 scripts/clip.py "#태그1" "#태그2" "#태그3" ...
```

- 전체 세트는 15~25개 권장 범위를 지키되 길어도 무방(사용자 선호). 핵심은 8~12개.
- **핵심 선정 기준**: 네이버 자동완성에 실제로 잡히는 조합 우선, 글의 각 섹션과 1:1 대응, 광역 태그(`#포켓몬` 등 경쟁 과열)는 핵심에서 제외.
- macOS 전용(`pbcopy`/`pbpaste`). 복사 후 반드시 `pbpaste`로 검증하고 두 블록의 개수를 각각 보고한다.
- 예외: 사용자가 "복사하지 마"라고 명시하거나, 아직 후보를 고르는 중이면 복사하지 않는다.

## 함정·주의
- 네이버는 `claude-in-chrome`(`*.naver.com` 차단)·computer-use(read 등급)가 막혀 **읽기는 curl이 정본**. 화면을 봐서 태그를 읽으려 하지 말 것 — 기존 글 태그는 `user_tag_style.py`가 더 정확.
- 본문 해시태그(글 맨 밑 평문)는 네이버의 **진짜 태그가 아님**(사이드바 태그 입력란이 진짜). 추천 태그는 사용자가 직접 태그란에 입력/붙여넣어야 검색에 잡힘.
- 새 글이 아직 티스토리 정리본으로 안 옮겨졌으면 3단계 검색이 비거나 적게 잡힌다 → 비슷한 카테고리의 **다른 검색어**로 템플릿 글을 찾거나 `--logno`로 직접 지정.
- Python `urllib`은 이 환경에서 SSL 검증이 막힘 → 스크립트는 전부 `curl` 백엔드.

## 의존 도구
- `curl`(아이폰 UA), `python3`(표준 라이브러리만)
- `scripts/related_keywords.py` — 네이버/구글 연관검색어
- `scripts/user_tag_style.py` — 기존 글 태그 형식 학습(티스토리 검색→네이버 백링크→tagNames 디코드)
- `scripts/clip.py` — 최종 태그를 한 줄로 클립보드 저장(확인 후, macOS `pbcopy`)

## 관련 스킬·메모리
