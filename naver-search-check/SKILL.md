# naver-search-check — 네이버 검색 노출(서치 블락) 검수

네이버가 특정 글의 검색 노출을 막았는지(품질/노출 필터), 아직 색인 전인지, 블로그 전체 문제인지
curl만으로 판별하는 스킬. 2026-07-13 실측 검증 — 노출 글(파레17)·블락 글(몬길9 원본)·삭제 글을
전부 정확히 분류했고, 재발행본의 색인 회복도 이 스킬로 확인했다.

## 실행
```bash
python3 scripts/check_search.py <URL_또는_logNo> [...]      # 특정 글
python3 scripts/check_search.py --recent 10                  # 최근 10개 일괄
```
출력: 글마다 `노출 OK / 미노출 / 글 확인 불가(삭제·비공개)` + 성공 쿼리, 마지막에 해석 요약.
exit 0 = 전부 노출, exit 1 = 미노출 존재(스크립트 체이닝용).

## 동작 원리
1. 글 제목을 가져와(`m.blog` curl, SSR 불안정 재시도 + **logNo 포함 여부로 진짜 글 페이지인지 검증**
   — 삭제/비공개 글은 블로그 홈으로 떨어져 엉뚱한 og:title이 잡히는 함정) 쿼리 후보를 만든다:
   `[카테고리] N.` 프리픽스 제거 → 전체 문구 + `:`/`-` 앞뒤 분리 문구.
2. `m.search.naver.com/search.naver?where=m_blog&query=...`에서 `blogId/logNo` 정확 매칭을 찾는다.
3. robots 메타에 noindex면 별도 표기(색인 자체가 막힌 것 — 노출 필터와 다른 문제).
4. `--recent`는 post-list API(스로틀 잦음, 재시도) → 실패 시 RSS 폴백으로 최근 글을 열거.

## 해석 가이드
- **일부만 미노출 + 나머지 노출** → 그 글 특이(살 노출 등 품질 필터 의심). 대응: 수정 재저장, 또는
  `/naver-to-naver` 재발행(+`censor_boxes.py` 가리기). 재발행 후 이 스킬로 색인 회복 재확인.
- **전부 미노출** → 블로그 단위 문제 또는 색인 지연. 네이버 서치어드바이저에서 확인(로그인은 사용자).
- **발행 직후 미노출** → 색인 전일 수 있음. 몇 시간 뒤 재검수.
- **글 확인 불가** → 삭제/비공개. 검색 노출과 무관하니 대상에서 제외.

## 함정
- 네이버는 WebFetch·claude-in-chrome 불가 — 전부 curl(아이폰 UA + Referer). 검색은 Referer를
  `m.search.naver.com`으로.
- 통합검색이 아니라 **블로그탭(where=m_blog)** 을 본다 — 통합검색은 노출 로직이 달라 오판함.
- 제목 전체 문구 매칭이 실패해도 부제 문구로 잡히는 경우가 있어 쿼리를 최대 3개 시도한다.
- 쿼리 사이 0.8초 간격 — 연속 타격 시 검색이 캡차/빈 응답을 줄 수 있음.

## 관련
- `/naver-to-naver` — 블락 글 재발행(+이미지 가리기). 재발행 전후로 이 스킬로 진단·확인.
- 메모리: `feedback_naver_no_webfetch`(curl 우회 정본).
