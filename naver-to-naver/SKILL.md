# naver-to-naver — 네이버 → 네이버 완전 마이그레이션

네이버 블로그 글 하나를 **누락 0으로** 네이버 새 글로 복제하는 스킬. 2026-07-13 몬길9(96컴포넌트,
이미지 55, GIF 5, 스티커 1, 문단 47+스페이서 294)로 엔드투엔드 검증 PASS.

## 두 가지 용도
1. **기존 글 재발행** — 검색 누락 글을 새 글로 재색인 유도. 새 글 발행 확인 후 **옛 글은 사용자가 직접 삭제**.
2. **다른 네이버 블로그 글 마이그레이션** — `--blog-id`로 소스 블로그 지정(URL로 주면 자동).

## 실행 (원샷)
```bash
python3 scripts/migrate.py <네이버_글_URL_또는_logNo> [--blog-id op5321] [--html <완전본.html>] [--dry-run]
```
실행 전 사용자에게 고지: **CGEvent 실제 마우스·키보드를 쓰므로 도는 동안(수 분) 건드리지 말 것.**
`--dry-run`은 네이버를 건드리지 않고 청크 빌드 + 원본 대비 누락 검사만 한다.

내부 파이프라인(전부 자동):
1. **fetch** — curl(아이폰 UA)로 m.blog 본문. SSR 골격(내용 문단이 빈 응답, 비결정적) 감지 시 자동 재시도,
   끝내 안 되면 `--html`로 완전본(브라우저에서 끝까지 스크롤 후 저장한 HTML) 요구.
2. **청크 빌드** — se-component를 DOM 순서로 걸어서:
   - se-text: 문단마다 원본 서식 보존 HTML(`font-size`·`<b>`·`color`·`align` 속성·빈 문단은 `<p><br></p>`
     스페이서 그대로 개수 보존). **background-color는 절대 안 넣음**(아래 함정).
   - se-horizontalLine: `<hr>`.
   - se-image/imageStrip/sticker: 원본 다운로드(규칙 아래) 후 파일 청크. 컴포넌트 안 캡션("짤 출처" 등)도 추출.
   - 인접 html 청크는 병합. 빌드 직후 **원본 문단 전수 대조** — 누락 있으면 붙여넣기 전에 중단.
3. **paste** — 새 글쓰기 탭(임시저장 팝업 자동 취소) → 본문 문단 클릭으로 포커스 → 청크 순차 Cmd+V.
   html은 문단 수 증가로, 이미지는 등록 확인(파일 크기 비례 대기, 대형 GIF 최대 60초)으로 검증 후 다음 진행.
4. **스타일 패스** — 이미지 전부 가운데정렬 + 구분선 전부 line3(가운데 꺾임)+center.
5. **하이라이트 패스** — 노란배경(#fff593) 소제목만 진짜 트리플클릭(신뢰 이벤트) →
   툴바 `background-color` 버튼 → `#fff593` 스와치로 입힘.
6. **제목 입력** — pbcopy 후 pbpaste로 클립보드 확인(다른 복사가 덮었을 수 있음) → 제목칸
   단일클릭→트리플클릭→Cmd+V. **검증·재시도는 최대 3회**(사용자 지시).
7. **최종 검증** — 에디터 실물을 img/hr 경계 단위로 원본과 대조: 텍스트 경계·이미지 수·노란배경 수.
   `PASS — 누락 0`이 나와야 성공. FAIL이면 어디가 다른지 로그로 찍힘.

발행은 하지 않는다 — 사용자가 검토 후 카테고리 지정하고 직접 발행(하드룰).

## 이미지 원본 규칙 (실측)
| URL 형태 | 결과 |
|---|---|
| 인라인/`?type=w966` | 966px 열화 프리뷰 |
| `postfiles.pstatic.net/<경로>` 쿼리 없음 | 14KB 썸네일(금지) |
| **`postfiles.pstatic.net/<경로>?type=w3840`** | **원본**(3840 미만이면 그 폭 그대로. GIF도 애니메이션 보존) |
| `blogfiles.pstatic.net/<경로>` 쿼리 없음 | 원본(위와 동일 바이트) |
| 스티커 `storep-phinf` | **`?type=p100_100` 필수**(쿼리 없으면 404, HEAD 미지원이라 GET으로) |
- 네이버 GIF는 동영상형 컴포넌트지만 `.gif` 경로를 w3840으로 받으면 다프레임 그대로(실측 73~120프레임).
- 파일명 `_s.jpg`는 `_s` 뗀 경로도 후보. 다운로드는 `~/.cache/naver-to-naver`에 캐시.

## 함정 (전부 실측 — 어기면 재발한다)
- **background-color를 paste HTML에 넣지 말 것(transparent 포함).** 연속 붙여넣기 중 SE가 하이라이트를
  이후 모든 문단에 고착시켜 글 전체가 노랗게 된다(47/8 사고). 노란배경은 반드시 하이라이트 패스로.
- **Cmd+Z로 수리하지 말 것.** undo granularity가 붙여넣기 단위가 아니라 이전 청크까지 되돌려 손상시킨다.
- **본문 포커스는 '문단 텍스트 자체'를 클릭.** 섹션 여백 좌표를 클릭하면 SE가 입력을 제목으로 라우팅해
  첫 청크가 제목칸에 붙는다(반복 사고). `document.activeElement` 체크는 무의미(캐럿이 hidden buffer iframe).
- **텍스트 정렬은 `<p align="center">`로.** paste 정규화가 `align` 속성·`<center>`는 살리고
  `se-text-paragraph-align-center` class와 `style="text-align:.."`은 제거한다.
- **이미지 등록 대기 없이 다음 청크를 붙이면 순서가 깨진다.** 등록(컴포넌트 수 증가) 확인 후 진행.
- **m.blog SSR은 비결정적 골격**을 준다(긴 글 일부 문단을 빈 zero-width로). 같은 curl이라도 재시도하면
  완전본이 오기도 함. 골격으로 빌드하면 그 텍스트는 영영 누락 — 빌드 단계 전수 대조가 막아준다.
- **native Cmd+A 복사도 불완전** — 에디터 가상 렌더 탓에 화면에 안 뜬 컴포넌트는 클립보드에 안 담긴다.
  "복사→이미지만 교체" 접근이 안 되는 이유.
- imageStrip(나란히 배치)은 개별 이미지로 풀려 들어간다(파일 붙여넣기로는 strip 생성 불가). 정보 손실은
  아니고 배치 차이 — 사용자에게 고지.
- 네이버 쓰기 자동화는 osascript+CGEvent만 유효(claude-in-chrome은 `*.naver.com` 하드블록).

## 노출 가이드라인 대응 (재발행 시 가리기)
검열은 **사용자가 직접 명시할 때만** 한다(기본 마이그레이션은 항상 원본 이미지 — 검열본이 캐시에
있어도 `--censored` 플래그 없이는 원본 백업을 쓴다). 명시 요청 시 전용 스킬 `/naver-photo-censor` 사용
(격자 싱글 좌표 판독 → 부위별 회색 박스 → 전 장 실물 검수 통과 후 진행). 가려진 캐시를 이
스킬의 migrate.py가 그대로 사용한다. 색인 회복 확인은 `/naver-search-check`.

## 하드룰
- **무인 발행 금지**(2026-06-16 사고) — 발행 클릭은 사용자. 실행 전 마우스·키보드 비접촉 고지.
- **옛 글 삭제는 사용자 몫**(영구 삭제는 금지 동작).
- **검증 PASS 없이 "완료" 선언 금지** — verify가 FAIL이면 원인을 잡고 재실행.
- 이모지 금지(스킬 산출물), SKILL.md 한국어.
