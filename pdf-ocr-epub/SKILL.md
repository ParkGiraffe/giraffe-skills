# PDF OCR과 EPUB 변환

스캔본 PDF는 글자가 그림으로만 들어 있어 검색도 복사도 안 됩니다. 이 스킬은 원본 그림을
그대로 둔 채 보이지 않는 텍스트 층만 얹어 검색 가능한 PDF를 만듭니다. 원본 픽셀을 건드리지
않으므로 OCR이 틀려도 눈으로 읽는 데는 영향이 없고, 나중에 더 좋은 엔진으로 다시 돌릴 수
있습니다.

텍스트 레이어가 이미 있는 PDF는 EPUB으로 바꿀 수 있습니다. 문단이 되살아나고 글자 크기를
바꿀 수 있어서 휴대폰과 전자책 단말에서 읽기 편해집니다.

## 엔진은 Vision을 씁니다

한국어 OCR에서 tesseract는 신뢰할 수 없습니다. 2026-09-17 실측에서 tesseract 5.5.2의
`kor` 모델은 `발뺌할`을 `wget`, `가엾게`를 `7G`, `결정을`을 `AVS`, `환원을`을 `BIS`로
읽었습니다. 한글 단어를 통째로 라틴 문자로 바꿔 놓는 증상이 문장마다 나왔습니다. 같은 쪽에서
macOS Vision은 전부 맞게 읽었습니다.

그래서 `scripts/visionocr.swift`가 `VNRecognizeTextRequest`를 감싼 작은 명령행 도구를
제공합니다. `ocr_pdf.py`가 알아서 빌드하므로 따로 준비할 것은 없습니다. Xcode 명령행 도구와
macOS 13 이상이 필요합니다.

## 작업 순서

### 1. 먼저 조사합니다

무엇이 OCR이 필요한지, 해상도가 쓸 만한지 보고 나서 움직입니다. 저해상도 스캔본에 시간을
쓰고 나서 결과가 엉망인 것을 발견하면 늦습니다.

```bash
python3 scripts/scan_pdfs.py "/경로/책폴더"
```

판정이 셋으로 나옵니다.

- `텍스트 PDF`: OCR이 필요 없습니다. EPUB 변환 후보입니다.
- `OCR 없음`: 스캔본입니다. OCR 대상입니다.
- `일부만 텍스트`: 섞여 있습니다. `ocr_pdf.py`가 쪽 단위로 판단하므로 그냥 돌리면 됩니다.

`그림 폭` 열을 봅니다. 본문 한 쪽의 그림이 1000픽셀을 넘으면 인식이 잘 됩니다. 900픽셀
아래면 오탈자가 눈에 띄게 늘어납니다. 사용자에게 미리 알리고 기대치를 맞춰 두십시오.

### 2. 원본을 백업합니다

결과는 새 폴더에 만들고 원본은 읽기만 하지만, 작업 전에 해시 대조가 되는 백업을 남깁니다.
`shutil.copy2`로 복사한 뒤 SHA-256을 다시 계산해 일치를 확인하고, 매니페스트를 남기면
나중에 원본이 손상됐는지 판정할 수 있습니다.

같은 디스크 안 복사는 실수로부터는 지켜 주지만 디스크 고장으로부터는 못 지킵니다. 그 점을
사용자에게 말해 두십시오.

### 3. OCR을 입힙니다

```bash
python3 scripts/batch.py ocr "/경로/원본폴더" "/경로/_OCR" --jobs 3
```

한 권만 할 때는 이렇게 합니다.

```bash
python3 scripts/ocr_pdf.py "입력.pdf" "출력.pdf"
```

`ocr_pdf.py`는 쪽마다 이미 텍스트가 있는지 보고 없는 쪽만 인식합니다. 그래서 스캔본과 텍스트
PDF를 한 폴더에 섞어 돌려도 됩니다. 텍스트 PDF를 통과시키면 결과 폴더 하나가 전부 검색
가능한 상태가 되므로, 사용자가 원본 폴더 대신 결과 폴더만 쓰면 되게 만들 수 있습니다.

속도는 Apple Silicon 기준 쪽당 0.5초 안팎입니다. 300쪽짜리 한 권에 3분 정도 걸립니다.
`--jobs 3`이면 300쪽 세 권을 같이 처리합니다. 오래 걸리므로 백그라운드로 돌리고 로그를
남기십시오.

### 4. EPUB으로 바꿉니다

```bash
python3 scripts/batch.py epub "/경로/원본폴더" "/경로/_EPUB"
```

`batch.py epub`은 텍스트 레이어가 있는 PDF만 고릅니다. 스캔본은 자동으로 빠집니다.

**스캔본을 OCR한 뒤 EPUB으로 만드는 것은 권하지 마십시오.** 검색 가능한 PDF는 원본 그림이
남아 있어 OCR이 틀려도 읽는 데 지장이 없지만, EPUB은 OCR 결과가 곧 본문입니다. 오탈자가
그대로 책이 됩니다. 도표와 코드 블록이 많은 기술서도 EPUB으로 흘려보내면 편집이 무너지므로
PDF로 두는 편이 낫습니다.

## 변환이 어떻게 돌아가는지

### OCR 텍스트 층

쪽에서 배경 그림을 원본 바이트 그대로 꺼내 Vision에 넘기고, 돌아온 줄 상자를 페이지 좌표로
옮겨 보이지 않는 텍스트(`render_mode=3`)로 심습니다. 그림을 다시 압축하지 않으므로 화질이
떨어지지 않습니다. 검증할 때 원본과 결과의 이미지 바이트가 같은지 대조하면 확실합니다.

글자 크기는 줄 상자 **너비**에 맞춰 계산합니다. 높이만 보고 정하면 글자가 페이지 밖으로
넘치고, 넘친 부분은 추출할 때 통째로 잘립니다. 실제로 이것 때문에 쪽마다 줄 끝이 사라진
적이 있습니다.

### EPUB

PDF에는 문단 개념이 없어서 줄바꿈만 남습니다. 되살리는 단서는 **줄 앞 공백**입니다. 조판
프로그램이 새 문단 첫 줄을 들여쓰기 때문에, 앞에 공백이 있는 줄은 새 문단이고 없는 줄은
앞줄에 이어 붙입니다. 이때 줄 끝 공백을 지우면 안 됩니다. `귀를 ` + `기울이며`가
`귀를기울이며`가 됩니다.

각주는 글자 크기로 가릅니다. 본문 크기의 0.72배 이하인 span만으로 이루어진 줄은 각주로 보내
장 끝에 모으고, 본문 줄 안에 섞인 작은 span은 `<sup>`로 감쌉니다.

장 나누기는 쪽의 첫 문단이 `3. 제목` 또는 `interlude` 꼴인지로 판정합니다. 라노벨 조판에서
흔한 형태입니다. 원본에 장 표시가 아예 없으면 장이 적게 나오는데, 이건 변환 오류가 아니라
원본이 그런 것입니다. 사용자에게 그렇게 설명하십시오.

## 검증은 반드시 합니다

돌려 놓고 끝내지 마십시오. 확인할 것이 셋입니다.

1. **쪽수가 같은가.** 원본과 결과의 `page_count`를 비교합니다.
2. **그림이 원본 그대로인가.** 표본 몇 쪽의 `extract_image` 바이트를 대조합니다.
3. **텍스트가 실제로 뽑히는가.** 결과 PDF를 다시 열어 `get_text`로 글자가 나오는지,
   `search_for`로 검색이 되는지 봅니다. 텍스트가 있는 쪽 비율이 60% 아래면 무언가 잘못된
   것입니다. 삽화가 많은 책은 낮게 나올 수 있으니 수치만 보지 말고 실제 쪽을 확인합니다.

EPUB은 본문 글자 수를 원본 PDF와 비교합니다. HTML 엔티티를 되돌린 뒤에 세야 합니다.
`&quot;`를 그대로 세면 따옴표 하나가 여섯 자로 잡혀 보존율이 110%처럼 나옵니다. 제대로
세면 100% 근처가 나와야 합니다. XML 파싱도 돌려 깨진 곳이 없는지 봅니다.

## 맥 파일 이름의 함정

**파일 이름이 NFD로 저장됩니다.** macOS에서 한글 파일명은 자모가 분리된 형태로 들어가는
경우가 많습니다. `os.listdir`로 받은 이름에 `'권'`을 정규식으로 맞추면 하나도 안 걸립니다.
비교나 정규식 전에 반드시 `unicodedata.normalize("NFC", name)`을 거치십시오. 셸 글로브
(`*권.pdf`)도 같은 이유로 빗나갑니다.

**복제본은 확장자가 깨져 있습니다.** 파인더에서 확장자를 숨긴 채 복제하면 `책.pdf의 사본`
처럼 `.pdf` 뒤에 말이 붙습니다. 확장자로 PDF를 거르면 이런 파일이 전부 빠집니다.
`".pdf" in name.lower()`로 판정하고, 결과물 이름은 `.pdf` 앞까지만 잘라 씁니다.

**exFAT에서는 `._` 짝꿍 파일이 생깁니다.** 결과 폴더에 `._책이름.pdf`가 파일마다 생기는데
확장속성 때문입니다. 작업이 끝나면 `dot_clean` 또는 `find . -name '._*' -delete`로
치웁니다. 조사할 때도 `._`로 시작하는 파일은 건너뛰어야 합니다.

## 산출물을 어디에 둘 것인가

원본 옆에 `_OCR/`과 `_EPUB/`을 만들고 원본 폴더 구조를 그대로 옮깁니다. 원본을 덮어쓰지
않으므로 언제든 되돌릴 수 있습니다. 원본 삭제나 교체는 사용자가 결과를 확인한 뒤에 따로
결정할 일입니다. 먼저 물어보지 말고 그냥 삭제하는 일은 없어야 합니다.

`batch.py`는 내용이 같은 파일(SHA-256 일치)을 한 번만 처리합니다. 같은 책이 여러 이름으로
있는 폴더에서 시간을 아낄 수 있습니다.

## 필요한 것

- macOS 13 이상, Xcode 명령행 도구 (`swiftc`)
- Python 3에 PyMuPDF (`import fitz`)
- tesseract와 ocrmypdf는 필요 없습니다
