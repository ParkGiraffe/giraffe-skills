# photo-folder-to-naver: 사진 폴더를 시간순으로 정리해 네이버 에디터에 올리기

## 전체 흐름

사진 폴더 하나를 받아 네 단계로 처리합니다. 스크립트 두 개가 전부 맡으므로 손으로 파일을 옮기거나 osascript를 새로 짜지 않습니다.

1. 얼굴 가리기가 필요한 사진이 있으면 `face-anonymizer`로 먼저 가리고, 가린 사진을 폴더 바로 아래에 둡니다.
2. `scripts/organize.py <폴더> --dry-run`으로 순서를 보고 사용자에게 보여 줍니다.
3. `scripts/organize.py <폴더>`로 영상 이동, 번호 붙이기, 워터마크를 한 번에 합니다.
4. `scripts/upload.py <폴더>/watermark`로 새 글쓰기 탭에 올립니다.

명령은 리포 루트에서 실행합니다. 두 스크립트 모두 리포 공용 `_lib/`(watermark, se_doc, chrome_window)를 씁니다.

## 1. 순서 확인 (dry-run)

```bash
python3 photo-folder-to-naver/scripts/organize.py "/Volumes/T7/블로그/팝업굿즈일지/포켓몬 고풍상점" --dry-run
```

출력은 종류별 장수, 시간순 구간(카메라 4장, 스크린샷 10장, 카톡 3장처럼), 찍은 시각을 모르는 사진 목록입니다.

찍은 시각은 이 순서로 찾습니다.

- EXIF 촬영 시각. 카톡으로 받은 사진도 원본 EXIF가 남아 있는 경우가 많습니다. 파일명 숫자(`1789984814621`)는 받은 시각이라 찍은 시각이 아닙니다. 파일명 순서대로 두면 카톡 사진이 전부 뒤로 몰립니다.
- 파일명 속 시각(`20260921_112814`, `Screenshot_20260921_113111_앱`, `IMG_2026-09-21-12153467`).
- 둘 다 없으면 카톡 받은 시각이나 파일 수정 시각으로 '추정'합니다. 추정한 사진은 보고서에 따로 나오므로 사용자에게 자리를 확인받습니다.

폴더 바로 아래 파일만 봅니다. `얼굴가리기` 같은 하위 폴더에는 가리기 전 원본이 들어 있을 수 있어서 섞으면 안 됩니다.

## 2. 정리 실행

```bash
python3 photo-folder-to-naver/scripts/organize.py "<폴더>"
```

- 영상(mp4, mov 등)은 `<폴더>/movies/`로 옮깁니다. 복사가 아니라 이동입니다. macOS가 만드는 `._` 짝 파일도 같이 옮깁니다.
- 사진은 `<폴더>/watermark/`에 `001_원래이름.jpg` 형식으로 저장합니다. 번호가 곧 올릴 순서입니다. 원본은 그대로 둡니다.
- 워터마크는 리포 정본 `_lib/watermark.py`의 확정 스타일입니다. 촬영 시각(EXIF)도 결과 파일에 남깁니다.
- 순서표는 `<폴더>/.photo_order.tsv`에 남습니다(번호, 원래 이름, 시각, 근거, 종류).
- `watermark/`가 이미 차 있으면 멈춥니다. 이전 결과와 섞이면 번호가 겹치기 때문입니다.

## 3. 에디터에 올리기

```bash
python3 photo-folder-to-naver/scripts/upload.py "<폴더>/watermark"
```

- 새 글쓰기 탭은 치지직, 유튜브 같은 방송 탭이 없는 크롬 창에 엽니다(`_lib/chrome_window.py`). 모든 창에 방송이 있으면 새 창을 만듭니다. 사용자가 창을 지정하면 `--chrome-window N`을 씁니다.
- 기존 글쓰기 탭은 닫지도, 비우지도, 이어 쓰지도 않습니다. 새 탭에 임시저장 글이 복원돼 비어 있지 않으면 멈춥니다.
- 사진은 에디터 API로 10장씩 넣습니다. 키보드와 클립보드를 쓰지 않으므로 사용자가 업로드 중에 컴퓨터를 써도 됩니다.
- 끝나면 파일명 번호 순서로 정렬하고, 에디터 문서에서 순서와 장수를 다시 읽어 확인합니다.
- 저장과 발행은 하지 않습니다. 사용자가 글을 쓰고 직접 발행합니다.

업로드가 중간에 실패하면 그 탭에 이어 올리지 않습니다. 탭은 그대로 두고 사용자에게 알린 뒤, 원인을 고쳐 새 탭으로 처음부터 다시 올립니다. 이어 올리면 어디까지 들어갔는지 헷갈려 순서가 꼬입니다(2026-09-26 실제로 꼬였습니다).

## 이미 열린 에디터에 올리기

기본은 새 탭입니다. 사용자가 굳이 지금 탭에 넣으라고 하면, 먼저 그 탭 문서를 읽어 비어 있는지 확인하고 사용자에게 알린 뒤 진행합니다. `blog.naver.com/op5321?Redirect=Write`로 연 탭은 에디터가 `#mainFrame` iframe 안에 있어서 JS를 iframe 문서에 주입해야 합니다.

## 함정 (실측)

- **에디터는 사진 파일명의 공백을 `_`로 바꿉니다.** 괄호는 그대로 둡니다. 원래 파일명으로 업로드 완료를 확인하면 `Pokmon GO.jpg` 같은 사진에서 완료를 못 보고 멈춥니다. `se_doc.append_images`는 사진 수로 완료를 보고, 이름 비교에는 `se_doc.editor_file_name`을 씁니다.
- **cv2.imwrite와 PIL 기본 저장은 EXIF를 버립니다.** 촬영 시각이 사라지면 시간순 정렬에서 자리를 잃습니다. 얼굴을 가리거나 원을 더 그린 사진은 `face-anonymizer/scripts/anonymize.py`의 `save_with_exif`로 저장합니다.
- **`upload_to_editor.open_fresh_tab`이 예전에는 창 1에 고정으로 탭을 열었습니다.** 지금은 `_lib/chrome_window`를 쓰도록 고쳤습니다. 새 탭을 여는 코드를 새로 짤 때도 `chrome_window.open_postwrite_tab`이나 `open_tab_front`를 씁니다.
- **백그라운드 실행은 `python3 -u`로 합니다.** `| tail`을 붙이면 출력이 끝날 때까지 안 보여서 멈춘 것을 늦게 알아챕니다.
